# Приложение Pokémon

Это Android-приложение, использующее [PokeAPI](https://pokeapi.co/docs/v2) для отображения списка покемонов с поддержкой поиска, фильтрации, офлайн-режима и пагинации. Приложение разработано на Kotlin с использованием современных технологий Android и следует трёхслойной архитектуре (data, domain, presentation).

## Функциональность

- **Список покемонов**: Отображает покемонов в двухколоночной сетке с именами и изображениями, с поддержкой пагинации.
- **Поиск и фильтрация**: Поддерживает поиск по имени или типу (например, "type:fire") и фильтрацию по нескольким типам или сортировку по критериям (номер, имя, HP, атака, защита) в порядке возрастания или убывания.
- **Офлайн-режим**: Кэширует данные покемонов локально с помощью Room, обеспечивая работу приложения без интернета для списка, поиска и фильтрации.
- **Pull-to-Refresh**: Позволяет обновить данные, очищая кэш и загружая новые данные из API.
- **Экран деталей**: Показывает подробную информацию о покемоне (ID, имя, изображение, типы, HP, атака, защита) при выборе (бонусная функция).
- **Навигация**: Использует Jetpack Navigation с кнопкой "назад" на экране деталей.
- **Обработка ошибок**: Отображает индикаторы прогресса при загрузке и сообщения об ошибках при проблемах с сетью, с возвратом к кэшированным данным в офлайн-режиме.

## Технологический стек

- **Язык**: Kotlin
- **UI**: Jetpack Compose
- **Сеть**: Retrofit с Gson
- **Локальное хранилище**: Room
- **Пагинация**: Paging 3
- **Загрузка изображений**: Coil
- **Асинхронность**: Coroutines и Flow
- **Навигация**: Jetpack Navigation
- **Дополнительно**: Accompanist SwipeRefresh для Pull-to-Refresh

## Архитектура

Приложение следует трёхслойной архитектуре:

1. **Слой данных (Data)**:
   - `PokemonRepositoryImpl`: Управляет загрузкой данных из PokeAPI и кэшированием в Room.
   - `ApiService`: Определяет сетевые запросы для получения списка покемонов и их деталей.
   - `PokemonDao` и `AppDatabase`: Управляют локальным хранением данных в Room.
   - `PokemonEntity`: Модель для базы данных с маппингом в/из доменной модели.

2. **Слой домена (Domain)**:
   - `Pokemon`: Доменная модель для данных покемонов.
   - `PokemonRepository`: Интерфейс, определяющий операции с данными (загрузка, поиск, фильтрация).
   - `GetPokemonsUseCase`: Инкапсулирует логику получения пагинированных данных покемонов.

3. **Слой презентации (Presentation)**:
   - `PokemonListViewModel`: Управляет состоянием UI, поиск, фильтрация, сортировка и пагинация.
   - `PokemonListScreen`: Отображает сетку покемонов с функциями поиска и фильтрации.
   - `PokemonDetailScreen`: Показывает подробную информацию о покемоне с кнопкой "назад".

## Проектные решения

1. **Jetpack Compose для UI**:
   - Выбран за современный декларативный подход, упрощающий разработку UI и интеграцию с управлением состоянием.
   - Используется `LazyVerticalGrid` для двухколоночной сетки и `ModalBottomSheet` для удобного интерфейса фильтров.

2. **Paging 3 для пагинации**:
   - Реализован через `PokemonPagingSource` для эффективной инкрементальной загрузки данных из API и Room.
   - Поддерживает начальную загрузку 60 элементов и последующие страницы по 20, оптимизируя производительность.

3. **Room для офлайн-кэширования**:
   - Локально сохраняет данные покемонов для работы в офлайн-режиме.
   - `PokemonPagingSource` возвращается к кэшированным данным при сетевых ошибках, обеспечивая бесперебойную работу.
   - Поиск и фильтрация (`searchPokemons`, `filterPokemonsByType`) работают с базой Room для офлайн-поддержки.

4. **Сортировка с SortedRoomPagingSource**:
   - Реализован кастомный `SortedRoomPagingSource` для динамической сортировки (по номеру, имени, HP, атаке, защите) через запросы Room, избегая сортировки в памяти для лучшей производительности.
   - Запускает загрузку из API при недостатке кэшированных данных, прозрачно обновляя данные.

5. **Фильтрация по нескольким типам**:
   - Поддерживает фильтрацию по нескольким типам путём объединения запросов Room для каждого выбранного типа с дедупликацией по ID.
   - Реализована через удобный интерфейс `TypeFilterChips` для выбора типов.

6. **Обработка ошибок и UX**:
   - Отображает `CircularProgressIndicator` при начальной загрузке и пагинации.
   - Показывает сообщения об ошибках сети с возможностью повтора и возвратом к кэшу в офлайн-режиме.
   - Экран деталей отображает сообщение "Pokemon not found", если покемон не найден в кэше.

## Инструкции по установке

1. Склонируйте репозиторий или скачайте исходный код.
2. Откройте проект в Android Studio.
3. Убедитесь, что в `build.gradle` указаны необходимые зависимости:
   - Jetpack Compose
   - Room
   - Retrofit
   - Coil
   - Paging 3
   - Accompanist SwipeRefresh
4. Синхронизируйте проект и запустите на эмуляторе или устройстве (рекомендуется API 21+).

## Известные ограничения

- **Обратная связь при пустых результатах**: Приложение не отображает явное сообщение "Нет результатов" при пустом поиске или фильтрации, хотя сетка остаётся пустой.
- **Тестирование**: Юнит-тесты и UI-тесты отсутствуют из-за ограничений по времени.
- **Данные экрана деталей**: Экран деталей зависит от кэшированного списка из ViewModel, что может привести к ошибке, если покемон отсутствует в текущих `PagingData`.
